System Architecture

How ScamShield AI Operates

A multi-stage threat detection pipeline combining sub-word character representations, balanced logistic regression classification, and deterministic heuristic signals.

1
Message Ingestion & Input Sanitization

The raw message string is submitted through the secure client interface. White-space boundary constraints, length verification (up to 5,000 characters), and validation rules ensure clean input formatting without data mutation.

Stage: Ingestion • Constraint: [1, 5000] chars
2
Character-Level N-Gram Decomposition

Unlike traditional word-level tokenizers that fail against deliberate misspellings (e.g. "b-a-n-k", "v3rify"), ScamShield decomposes text into overlapping character sequences ranging from 3 to 5 characters, capturing sub-word patterns and evasion tactics.

Analyzer: char • N-Gram Range: (3, 5) • Min DF: 2
3
TF-IDF Vector Space Projection

The decomposed character n-grams are mapped into a high-dimensional vector space using the pre-fitted Term Frequency-Inverse Document Frequency (TF-IDF) vectorizer, weighting distinctive sub-word patterns across a vocabulary of 20,000 features.

Dimensionality: 20,000 features • Model artifact: scam_detector_vectorizer.pkl
4
Logistic Regression Classification

The vectorized sample is processed by the trained multi-class Logistic Regression classifier. Optimized with balanced class weighting, the model accounts for class distribution variance across legitimate, spam, and smishing samples.

Classifier: LogisticRegression(C=1.0, class_weight='balanced') • Artifact: scam_detector_model.pkl
5
Calibrated Probability Distribution

The classifier outputs posterior class probabilities via predict_proba() for Ham, Spam, and Smishing. This granular distribution enables transparent risk stratification rather than an opaque binary threshold.

Classes: ['ham', 'smishing', 'spam'] • Target: Probability Calibration
6
Synthesized Risk & Supporting Heuristics

The primary prediction determines the core threat verdict (Low, Medium, or High Risk). Concurrently, an independent deterministic scanner flags contextual signals (such as embedded URLs, shortcodes, and KYC demands) to provide immediate situational awareness.

Heuristics: 10 Pattern Detectors • Response: JSON Schema
Explicit Distinction: ML Inference vs. Rule-Based Heuristics

The machine learning prediction is completely autonomous: Text classification is derived solely from the mathematical weights of the character TF-IDF vectorizer and Logistic Regression classifier. The "Potential Message Signals" displayed in the interface are rule-based heuristic indicators provided for contextual triage; they do not constitute the ML model's internal statistical reasoning or activation weights.

Product Overview

About ScamShield AI

An independently engineered cybersecurity solution providing real-time text message threat intelligence and classification through local machine learning.

Sub-Millisecond Inference

Pre-compiled vectorization matrices and lightweight Logistic Regression enable sub-millisecond threat evaluation without latency bottlenecks.

Probability Calibration

Outputs full posterior class distributions across Ham, Spam, and Smishing rather than rigid opaque binary flags.

Transparent Risk Triage

Centralized risk classification categorizes inputs into Low, Medium, or High risk with tailored defensive guidance.

Deterministic Heuristics

Independent rule-based scanning detects explicit threat indicators such as urgent keywords, banking terms, KYC claims, and malicious URLs.

Actionable Safety Guidance

Delivers targeted defensive protocols whenever malicious content is flagged to prevent unauthorized credential disclosure.

Explainable Architecture

Maintains separation between statistical ML inference and rule-based heuristic tags, preventing false attribution of AI reasoning.

Zero-Persistence Privacy Principle

User submissions are evaluated entirely in-memory on the local server. Messages are never stored in databases, never written to persistent disk logs, and never transmitted to external third-party AI APIs (such as OpenAI, Gemini, or external cloud LLMs). Your data remains isolated within your operational environment.
